# Working on realism-gap

- Read `docs/build-plan.md` for the goal, current stage, and acceptance criteria.
- If present, read `MEMORY.md` for local progress, checks, and the next bounded step.
  Update it after each work session. It is intentionally ignored by Git; never force-add it.
- Work one requested stage at a time. Finish its checks and summarize the result before
  expanding scope. Keep commits small and specific to the completed step.
- Distinguish proposed work, inspected code, executed checks, and measured results.
  Mock outputs are plumbing checks and must never appear as benchmark findings.
- Human labels, human baselines, and claims of human authorship must come from actual
  human work. Record AI assistance accurately in `docs/AI_USE.md`.
- Local commits, GitHub publication, paid model runs, and dashboard deployment are
  separate steps. Follow the user's authorization for the current session.
